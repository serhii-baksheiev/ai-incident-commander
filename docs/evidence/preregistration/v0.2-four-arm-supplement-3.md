# Preregistration supplement 3: the model roles emit a structured cause, prompt `reference-roles-prompt-v0.5`

Written on 2026-09-28, before any paid run under
`reference-roles-prompt-v0.5`. It records the owner's AIC-123 decision D4
(Jira AIC-123, 2026-09-25): the model roles emit a structured hypothesis cause
before the AIC-121 calibration, with prompt v0.5 and this supplement.

It supersedes one row of `v0.2-four-arm.md`'s table "What is fixed before any
result exists": the graph arm's prompt version, which supplement 2 had moved to
`reference-roles-prompt-v0.4` and which this supplement moves to v0.5. Every
other row of `v0.2-four-arm.md`, supplement 1 and supplement 2 stands as
registered.

## Every graph-model hypothesis carries a structured cause

`generate_hypotheses` and `challenge_hypothesis` now answer with a cause on
every hypothesis: a component, a mechanism from the closed vocabulary, and an
optional trigger. The provider schema requires it, and the role refuses an
answer without one.

- See cause-emitting-roles.test.mjs › "createModelGenerateHypotheses: the
  provider schema declares a closed cause object on every hypothesis item,
  required, with the mechanism enum equal to the supplied vocabulary exactly"
  and › "createModelChallengeHypothesis: the provider schema declares a closed
  cause object on alternative, required, with the mechanism enum equal to the
  supplied vocabulary exactly".
- See cause-emitting-roles.test.mjs › "createModelGenerateHypotheses: refuses a
  hypothesis carrying no cause" and › "createModelChallengeHypothesis: refuses
  an alternative carrying no cause".
- A mechanism outside the vocabulary is refused, by the same check the
  conclusion role uses. See cause-emitting-roles.test.mjs ›
  "causeMechanismViolation: generate_hypotheses' off-vocabulary refusal message
  carries exactly what causeMechanismViolation returns for the same cause and
  vocabulary — one implementation".

A refused answer is the role's measured result. There is no repair round, as
before.

The scripted-control arm is unchanged: its hypotheses carry no cause, so the
control baseline does not move.

## The generate and challenge roles see the mechanism vocabulary

Both roles' system prompts now carry the vocabulary sentence that the naive
role and the conclusion role already showed. It is one sentence, built in one
place, and all four roles show it. The graph arm's hypothesis-forming roles
therefore see the same three-class answer space the naive arm already saw:
parity between the arms improves, and nothing the naive arm sees is taken
away.

- See cause-emitting-roles.test.mjs › "describeMechanismVocabulary returns the
  exact sentence every mechanism-vocabulary role must show", ›
  "generate_hypotheses' system prompt contains
  describeMechanismVocabulary(vocabulary) for the vocabulary it was given", ›
  "challenge_hypothesis' system prompt contains
  describeMechanismVocabulary(vocabulary) for the vocabulary it was given" and
  › "the naive role's system prompt contains
  describeMechanismVocabulary(vocabulary) for the vocabulary it was given".
- The lane gives both roles `ROOT_CAUSE_MECHANISMS`. See lane-arms.test.mjs ›
  "modelNodes(record, port).generate_hypotheses and .challenge_hypothesis are
  given the mechanism vocabulary evals.ROOT_CAUSE_MECHANISMS: the provider
  schema's cause mechanism enum equals it exactly, and the system prompt
  carries the vocabulary sentence".

## Later roles see the cause

The model is shown each hypothesis as the state holds it, so a cause written by
`generate_hypotheses` or `challenge_hypothesis` reaches the prompts of the
roles that run after it. See cause-emitting-roles.test.mjs › "a hypothesis
cause in state reaches the interpret, challenge and conclusion prompts".

No scenario id reaches a prompt through the cause: a mechanism is a vocabulary
class, never a scenario id. See model-prompt-scenario-leak.test.mjs › "shows
no REPLAY_SCENARIOS id in any model prompt, for every scenario and every
model-backed role".

## Nothing else changes

The status rules, termination, the metrics, the partitions, the run count and
the information mode stand as registered. The cause is not yet read by any
prediction path; the deterministic prediction path (AIC-124) will be
registered in a further supplement before AIC-121 runs.
