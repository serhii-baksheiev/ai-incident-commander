# Preregistration supplement 8: challenge_effect needs a discriminating trial

Written on 2026-09-29, before any paid run. AIC-138 closes the known limit
supplement 7 recorded: `challenge_effect` passed on a change of leader or of
the leader's status with no discriminating trial.

Every row of `v0.2-four-arm.md` and supplements 1 to 7 stands as registered,
except where a section below says it replaces one. The replaced rows stay in
their files as written.

## Evaluator: replaced

`v0.2-four-arm.md` registered the evaluator `behavior-evaluators-v0.3`. From
this supplement on the live lane and the final hold-out declare
`behavior-evaluators-v0.4`. See lane-arms.test.mjs › "both
eval-live-model.mjs and eval-final-holdout.mjs import oracleArm and naiveArm
from ./lane-arms.mjs, wire them into runLiveModelLane, and declare the lane's
evaluator behavior-evaluators-v0.4". The ground truth stays
`structural-ground-truth-v1`.

## The rule

Under `behavior-evaluators-v0.4`, a `challenge_effect` pass needs at least one
executed discriminating trial, counted as supplement 7 defines it. A change of
leader or of the leader's status without one scores 0 with the reason
`no-discriminating-trial`. See challenge-effect-discriminating-evaluator.test.mjs
› "under behavior-evaluators-v0.4, a challenge that changes the leader as
expected with no executed discriminating trial scores 0 with reason
no-discriminating-trial", › "under behavior-evaluators-v0.4, a challenge that
changes only the leader's status with no executed discriminating trial scores 0
with reason no-discriminating-trial" and › "under behavior-evaluators-v0.4, a
challenge that changes the leader as expected with one executed discriminating
trial scores 1 passed, tagged behavior-evaluators-v0.4".

This replaces the known-limit sentence in supplement 7's "Discriminating
credit" section.

On every calibration scenario, `evidence_coverage`,
`misleading_evidence_handling` and `false_alert_correctness` score as they did
under v0.3 for the same outcome. See
challenge-effect-discriminating-evaluator.test.mjs › "v0.4 scores
evidence_coverage, misleading_evidence_handling and false_alert_correctness
exactly as v0.3 on every calibration scenario for the same outcome".

## Earlier versions and records

Under v0.2 and v0.3, a change of leader without a trial still passes. See
challenge-effect-discriminating-evaluator.test.mjs › "the
leader-change-without-trial observation still scores 1 passed under
behavior-evaluators-v0.3 and behavior-evaluators-v0.2". A record keeps the
version that scored it, and an unknown version is refused. See
challenge-effect-discriminating-evaluator.test.mjs › "evaluateBenchmarkRecord
refuses behavior-evaluators-v0.99, naming v0.2, v0.3 and v0.4". No committed
record is rescored.

## Controls

The Oracle reaches its best value on every metric under v0.4, `challenge_effect`
included. See challenge-effect-discriminating-evaluator.test.mjs ›
"docs/evidence/oracle/behavior-evaluators-v0.4.json deep-equals a fresh run of
scripts/eval-oracle.mjs --evaluator-version behavior-evaluators-v0.4, and
reaches best on every metric including challenge_effect".

The scripted-control baselines are unchanged. See lane-arms.test.mjs › "the
committed control baseline files each equal what the scripted control arm
observes under behavior-evaluators-v0.4 — control-baseline.json for
final-evaluation, control-baseline-calibration.json for calibration — with no
axis missing and none extra".

## What this does not settle

AIC-103 asks what an evaluator version has to promise when scoring semantics
change. This supplement uses a new version for one such change. It does not
answer the general question, and AIC-103 stays open.

## Candidate identity

The change touches `packages/` and `scripts/`, so it moves the candidate
fingerprint. A calibration or hold-out run admitted after this supplement is
scored under `behavior-evaluators-v0.4`.
