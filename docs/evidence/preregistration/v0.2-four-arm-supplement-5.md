# Preregistration supplement 5: how the observation table reaches the investigation

Written on 2026-09-28, before any paid run. Supplement 4 registered the
observation table `observation-annotations-v1` and said that how it reaches
the investigation, and that the arms see the same evidence, would be
registered in the supplement that wires it. This is that supplement (AIC-123
slice 3b).

Every row of `v0.2-four-arm.md` and supplements 1 to 4 stands as registered.

## Where the facts enter

The facts enter at the replay boundary, as `Evidence.observation`, on exactly
the evidence items the table gives facts for. The fixtures are not edited:
the replay adapter returns new evidence objects and leaves the recorded
fixture as it was.

- See observation-merge.test.mjs › "ReplayToolAdapter given { observations }
  merges facts only onto the item the annotator returns a non-empty list for,
  as a new object equal to the item plus observation:{version,facts}, leaves
  the other item untouched, and never mutates the caller's own fixture
  object".
- See observation-merge.test.mjs › "createObservationAnnotator returns a
  function that, for every (replay identity, evidence id) pair the ok corpus
  serves, answers the facts of its own OBSERVATION_ANNOTATIONS row".
- The table only speaks for the prose it was reviewed against. See
  observation-merge.test.mjs › "createObservationAnnotator throws a plain
  Error naming the evidence id when a row matches the (identity, evidence id)
  pair but the served evidence's statement differs from the row's statement".

## The arms see the same evidence

The scripted-control arm and the graph-model arm receive identical evidence,
observations included. See observation-merge.test.mjs › "scriptedNodes(record)
and modelNodes(record, port), replayed through execute_investigation for every
calibration and hold-out scenario, produce identical state.evidence between
the two arms, carrying an observation exactly on the items
OBSERVATION_ANNOTATIONS gives non-empty facts".

## No model sees the facts

The facts are the deterministic evaluator's channel. The naive arm never sees
them, so the graph arm's model roles must not see them either: the state the
model is shown leaves `observation` out, and its prompt is the same with or
without it. See observation-merge.test.mjs › "describeState strips
evidence[].observation from what a model role is shown:
interpret_residual_evidence's prompt is byte-identical whether or not the
state's evidence item carries an observation, and never contains the key or a
fact value unique to it".

So the prompt version does not move, and the information each model role
sees is unchanged by this supplement.
